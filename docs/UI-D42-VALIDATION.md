## 1. 输入框边界：高对比度与强光

- 普通状态：1px 透明边框，内阴影与原型完全一致。
- Chromium `forced-colors: active` 模拟：阴影变为 `none`，浏览器将输入框边框映射为系统颜色（测得 `rgb(55, 0, 110)`），宽度仍是 1px。截图中输入框边界可见；未添加 `forced-color-adjust: none` 或自定义高对比度样式。
- `reducedContrast` 视觉模拟中，浅内阴影明显变淡，输入区域边界难辨认。这只能提示风险，不能代替真实户外强光和不同设备屏幕测试。
- 证据：`forced-colors.png`、`reduced-contrast.png`。没有据此加深阴影或添加描边。

## 2. 字体放大

- 调用 Chromium `Emulation.setEmulatedOSTextScale`，比例 2：本环境下固定 px 字体未变化，栏号 / 提示仍为 11px，步骤名仍为 10px。因此不能把“没有溢出”解释成已通过系统大字体支持。
- 另对测试页面中所有已渲染字体做 200% 放大压力检查（只改测试 DOM，不改仓库样式）：栏号 / 提示成为 22px、步骤名 20px。说明文字能换行，页面整体没有横向溢出；步骤条名称发生挤压，测得第一项文字内容宽度超出容器，截图中相邻名称过近。
- 日期框和底部操作仍显示，但这不是对所有系统字体设置或辅助功能的全面认证。实际 iOS / Android 大字体还需设备验证。
- 证据：`os-text-scale-200.png`、`text-stress-200.png`、`report.json`。没有自行调整字号、换行或步骤布局。
