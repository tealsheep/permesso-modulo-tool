## 3. 每种类型要做的事

**Claude（数据，`data/`）**：
1. 上网核实该类型的官方子页：要哪些表、首次签发由谁填、续签要的材料。写进 `docs/research/`。
2. `application-types.json`：加一条，包括 moduli、operations、sportelloUnicoFills、feeRule。
3. `fees.json`：contributo 档位。例如学习类按 ≤1 年 €40；家庭跟随担保人期限。不确定就按 D26 的规则，旁注"请在邮局窗口确认"。
4. `materials/<code>.json`：意大利文原名 + 中文，附条件。
5. `questions.json` 和 mapping：新问题的文案（例如学习类的学校、考试、保险；家庭类的担保人）以及字段映射、条件。
6. 每种类型一份虚构样例，供端到端测试。

**Codex（代码）**：
- 只在数据格式表达不了时改代码，例如新问题需要新的输入组件。
- 每批加端到端测试：生成 PDF、核对格子。
- 截图只在画面变化时按 D42 先写原因再更新。

## 4. 节奏

- 一批做完、测试通过、Claude 审查后，再开始下一批。
- 每批开工前，Claude 在 HANDOFF 写明本批的类型和要改的数据文件。
- A 批开工前要用户确认：分批顺序，以及学习类（24 / 31）是否要支持"学生有工作收入时加 Modulo 2"。
